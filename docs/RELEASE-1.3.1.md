# v1.3.1 · 荣耀 / 安卓互动动画兼容修复

针对睡觉、沙发、野餐三段互动在部分安卓浏览器出现背景色块或脏边的问题，增加透明 WebP 动画回退。走路 PNG 精灵图不受影响。

## 修改

- 检测到 Android、HarmonyOS 或 HONOR 浏览器标识时，直接使用透明 WebP，不加载 WebM，也不依赖小尺寸视频探测。
- 其他设备探测完成前显示透明 PNG 静帧；探测成功使用 WebM，失败或 3 秒超时后当前互动自动切换 WebP。
- 实际视频加载或解码报错时回退 WebP；WebP 加载失败时保留静帧。
- 播放中启用“减少动态效果”会恢复静帧，关闭后恢复播放。
- 动图退场移除元素，重进时新建；迟到的加载回调不会复活已退出的场景。
- 保留首页“连接 AI”入口。资源版本号更新为 `honorfix1011-v2`。

原 WebM 实际带有 alpha。不能单凭 `ffprobe` 显示 `yuv420p` 判断其没有透明通道；小尺寸探测片也不足以证明手机完整视频的硬件解码和合成路径正常。

## 升级

先停止本机服务并备份现有私人数据目录，将新版源码合并到原项目目录，保留原 `data/` 中的存档和钥匙，然后按原方式启动。不要删除整个数据目录，不要把私人数据上传到仓库。

使用 Docker、Render 或 Cloudflare 的用户需更新自己的部署源码并重新构建或部署；仅下载压缩包不会更新已部署的网站。继续保留现有卷、持久磁盘、Durable Object 和 Secret，详见[部署与备份](DEPLOY.md)及 [Cloudflare 升级说明](CLOUDFLARE.md)。本次没有更改后端、存档格式或认证配置。

特殊浏览器若以“桌面模式”隐藏手机标识，可在游戏网址查询参数中加 `duoAnimation=webp` 强制兼容模式：无参数时加 `?duoAnimation=webp`，已有参数时加 `&duoAnimation=webp`。不影响账号数据。

## 验证范围

候选代码在真实桌面 Chromium 155 中完成 14 项自动化检查：

- 桌面正常播放 WebM，不请求 WebP。
- 模拟 Android 标识后三段互动均使用 WebP，零 WebM 请求（包括探测片）。
- 手动兼容模式。
- 提前进入互动时，探测等待期间保持静帧，成功/失败后切换正确。
- 探测超时回退。
- 实际视频失败后回退。
- WebP 失败保留静帧。
- 退出场景后迟到的图片加载不会复活场景。
- 初始减少动态效果设置。
- WebP、WebM 两条路径在播放中切换减少动态效果。
- 野餐保持末帧，再次进入从头播放。
- 游戏首页除两处动画缓存版本号外保持原样。

本机 10 项回归、Cloudflare 2 组集成测试及上游 smoke / parity 检查通过。已确认合入的 7 个前端文件与通过上述浏览器测试的候选包逐字节一致。

JavaScript 语法检查通过。三张 WebP 全部是 RGBA 动画：睡觉 60 帧、沙发 62 帧、野餐 62 帧；野餐只播一次。

以上浏览器检查使用真实脚本、样式和素材，在隔离的场景容器中运行；Android 标识和网络故障由测试模拟。**未做荣耀真机验收，不代表所有手机、浏览器或完整游戏流程都已实测。** 发布提交另由 GitHub Actions 检查 Node 20 / 22、Docker 和 Cloudflare，结果见仓库 Actions。

更新后请在原来的手机和浏览器中确认三段互动有无色块、野餐第二次能否重播，以及昼夜切换是否正常。如仍异常，请提供手机型号和浏览器名称即可。
